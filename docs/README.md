# Project Documentation

This directory contains documentation for the project, including Git standards, workflows, and other reference materials for developers.

## Contents

- **git-standarts.md** → Defines the branching strategy, commit message conventions, and code review process for the team.
  - Branching Strategy: main, develop, feature/*, hotfix/*, release/*
  - Commit Message Convention: `<type>(<scope>): <description>` (types include feat, fix, docs, style, refactor, test, chore)
  - Code Review Process: Steps from feature branch creation to merge after approval

## Purpose

- Provides a single source of truth for coding and Git workflow standards.
- Helps new team members onboard quickly.
- Ensures consistency in commits, branching, and code reviews.

## How to Use

- Read `git-standarts.md` before creating new branches or commits.
- Follow the conventions when writing commit messages.
- Follow the code review process when submitting pull requests.
